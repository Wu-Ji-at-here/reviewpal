# 复盘通项目 · AI 协作手册

### 我是小白，该怎么"提示"AI 帮我把这个项目做出来

> 配套文件：《复盘通项目设计文档_OPC黑客松_V1.5.docx》、`review-record.schema.json`
> 核心用法：**把 V1.5 文档的 8 项 P0 验收当成 8 个关卡，每次只让 AI 带你过一关。**

---

## 一、总纲（一句话）

> 不要问"帮我做复盘通"，要问"帮我做完 P0 的第 3 关"。

AI 不是不能做，是"信息给太少 + 目标太大"时才容易跑偏。你只要守住两条：**一次一关**、**贴原文**。

---

## 二、每次对话的固定开场（照抄这三句）

```
我在做「复盘通」黑客松项目，设计文档在 复盘通项目设计文档_OPC黑客松_V1.5.docx（附件 F 是数据契约）。

我在第 ___ 关（P0 第 ___ 项：____________）。
今天的目标：____________________。
现在的现象 / 报错原文：
（把终端或浏览器里的报错整段粘过来，不要转述）
```

把上面三段填满再发送，AI 的输出质量会立刻不一样。

## 三、五个阶段的提问模板（复制即用）

### 阶段 0 · 环境打通（文档里的 D0）

- "我完全不懂命令行，用的是 Windows PowerShell。请给我从零到'模型返回一句话'的每一步命令，每步都写明：输入什么、期望看到什么、出错时怎么排查。"
- "请帮我确认 Node 版本、Agent 运行时是否装好，并给我 3 条自检命令。"
- "我的 `.env` 写好了但好像没生效，帮我列 5 个最可能的原因和排查顺序。"

### 阶段 1 · P0 骨架（D1）

- "请给我一个最小可跑的项目骨架：后端 Node + Express、前端 React。**先只做 P0 第 1、2 项**（真实调用模型 + 输出通过契约校验）。要求：每个文件给完整内容、给运行命令、给验收方法。"
- "先不要一次给我太多代码，只做后端一个文件。"
- "请帮我写调用模型的函数，要求：先剥掉代码围栏、再 `JSON.parse`、失败重试一次、仍失败走兜底模板。"
- "把这个 JSON 输出接到附件 F 的契约上做校验，用 zod，给我代码和一条失败的测试用例。"

### 阶段 2 · 加固（D2）

- "按文档 11.2 的危机规则实现熔断：命中关键词就**不调用模型**，直接返回 `crisis` 结构。给我一份高召回关键词表 + 代码。"
- "帮我把 API Key 从前端移到后端，给我改动前后的对比和一个'验证 Key 不会出现在浏览器请求里'的检查方法。"
- "给我 React 版的免责声明页脚 + 敏感信息单独同意弹窗，文案用文档 10.4 里那两段。"

### 阶段 3 · 内测与评测（D3）

- "帮我设计 3 个测试输入：正常记录 / 强负面情绪 / 危机信号，并写出每个的期望结果。"
- "按文档 12.3，帮我写一个'反说教命中率 + 微建议可执行率'的评分脚本，模型初判 + 我人工抽检 10 条。"
- "帮我做一张给种子用户填的打分表（含'是否感到被说教'5 分制那一题）。"

### 阶段 4 · 演示与材料（D4–D5）

- "按附件 E 的模板，帮我生成这几天的 `worklog.md`（每天的'人类决策点'一栏必须是真的）。"
- "把文档 15.1 改写成 60 秒可背下来的口语逐字稿，句子要短。"
- "帮我列出《人机协同工作流说明书》需要的材料清单，我逐项去补。"
- "帮我做一个 6 页 PPT 大纲：钩子 / 演示动线 / 三个机制 / 证据 / 商业 / 团队。"

### 阶段 5 · 现场应急（上台前）

- "给我一张'上台前 10 分钟检查清单'，我要逐项打勾。"
- "如果现场模型调用失败，请给我'一键切到 Mock'的操作步骤。"
- "评委问 XX，我该怎么答？请给 3 句以内的答案。"

## 四、让 AI 输出可控的 7 条要求（每次聊天都带上）

1. **一次只改一个文件 / 一个功能**——不然上下文一乱，代码就跑不起来。
2. **给我能直接粘贴运行的完整文件**，不要"……此处省略"。
3. 每段代码后面给**验收命令**和**期望输出**，我要能自己判断对错。
4. 我贴报错时：**先给最小修复**，再用大白话解释原因。
5. 碰到密钥：明确告诉我"**这一行绝对不能进前端**"。
6. 模型名、价格、热线这类**时效信息**，请标注"需你到官网核对"，不要直接生效。
7. 每次结束给我"**下一步 3 件事**"，我照着做就行。

## 五、三类万能句（不懂的时候直接说）

- "我完全不懂，请**逐行**解释这段代码在干什么。"
- "把这段**改成人话**，我要讲给评委听。"
- "这里是不是有多种方案？**用表格比较优缺点**，并直接推荐一个给我。"

## 六、小白最容易卡住的 10 个点（先存下来）

1. Node 版本低于要求（文档要求 22.19+）。
2. 全局安装权限报错（PowerShell 用管理员或改用官方安装脚本）。
3. 端口被占用（后端 3000/5000 被别的程序占了）。
4. 前端调后端出现 CORS 报错（要开后端跨域）。
5. `.env` 改了没生效（要重启服务，不是刷新浏览器）。
6. 模型返回的不是纯 JSON（要剥代码围栏 + try/catch）。
7. API 余额不足或 Key 写在前端（演示前必查）。
8. 路径里有中文或空格导致命令失败。
9. PowerShell 执行策略拦住脚本（用 `-ExecutionPolicy Bypass`）。
10. 演示当天网络不稳（提前准备 Mock 开关 + 录屏）。

## 八、最后一句

**你不需要会写代码，你需要会"下指令 + 验收"。**
每一关都问自己三个问题：能不能跑起来？跑出来的东西对不对？评委看了能不能看懂？——三个都能答"能"，就过关，别恋战。
