# 复盘通 · 演示与部署指南

> ⚠️ **本期范围说明（V1.8）**：展示墙**只展示本人卡片**，**不做陌生网友互看/点赞/评论**。
> 本文档的"路线 A/B"仍然是**让评委/朋友能访问到你这个项目**的正确做法（演示需要）；
> 但"陌生人互相互动"部分已移入**发展前景**，见文末第五节，本期不演示、不承诺。

---
> 结论先说：**代码已经是"可上公网的多用户应用"了**——展示墙、点赞（按访客去重）、评论、昵称、举报、撤下权限全都是跨设备的。
> 现在别人看不到，**唯一的原因是它跑在你自己的电脑上（localhost:8787）**。

## 一、为什么现在别人看不到

| 名词 | 意思 | 现在的情况 |
|---|---|---|
| `localhost` / `127.0.0.1` | "本机"的意思 | 只有这台电脑能访问 |
| 公网 IP / 域名 | 互联网上任何人都能访问的地址 | ❌ 还没有 |
| 数据存放在哪 | SQLite 文件 `reviewpal/data/reviewpal.db` | 在你这台电脑上 |

部署到公网服务器后，**所有访问者共用同一台后端**；本期打卡墙只展示本人的卡片（接口按归属过滤）。

## 二、三条路（按小白友好度排序）

### 路线 A · 内网穿透（5 分钟，适合"先给朋友看一眼"）

在自己电脑上装一个穿透工具，把 `localhost:8787` 临时映射成一个公网网址。电脑关机就失效。

- 工具：`cloudflared`（免费，命令一行）、花生壳、nps 等
- cloudflared 示例：`cloudflared tunnel --url http://localhost:8787`
- 得到形如 `https://xxxx.trycloudflare.com` 的网址，发给朋友即可访问
- ⚠️ 缺点：临时、不稳定；**你的电脑必须一直开着**

### 路线 B · 云服务器（推荐，正式做法）

1. 买一台**轻量应用服务器**（阿里云/腾讯云，学生机约 100 元/年；想免备案就选香港/新加坡节点）
2. 装 Node（Debian/Ubuntu 示例）：
   ```
   curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
   sudo apt install -y nodejs
   node -v          # 应 ≥ 22.19
   ```
3. 把整个 `reviewpal` 目录上传上去（不含 `data/`，那是你本机数据）
4. 让它常驻运行（关掉终端也不停）：
   ```
   sudo npm i -g pm2
   cd reviewpal && pm2 start server/index.js --name reviewpal
   pm2 save && pm2 startup
   ```
5. 服务器安全组放行端口 `8787`（或用 Nginx 反代到 80/443）
6. 访问 `http://<你的服务器IP>:8787` —— **到这里，陌生人就能互看卡片了**

> 想用域名 + HTTPS：装 Nginx 反向代理到 8787，再用 certbot 申请免费证书。
> ⚠️ **国内服务器 + 域名需要 ICP 备案**；不想备案就用境外节点。

### 路线 C · Serverless（Vercel / Cloudflare）

能用，但**要注意**：现在用的是一个 SQLite 文件，Serverless 环境没有持久磁盘，重启就丢数据。要走这条路必须先换成云数据库（如 Postgres / Turso / Supabase）。**不推荐小白第一次就选它。**

## 三、本期范围与安全设计（代码里已经做了）

陌生人社区和"私人工具"是两种东西。以下四条是**最低限度**，已全部实现：

| 要求 | 实现方式 |
|---|---|
| **默认私有** | 记录 `public = false`；不勾选同意永远不会出现在公开页面 |
| **只能管自己的** | 卡片记录归属 `owner`；别人撤不下你的卡（实测返回 403"这张属于 小明"） |
| **归属校验** | 卡片记录发布者；非本人撤下返回 403（实测通过） |
| **不做跨用户互动** | 点赞 / 评论 / 举报**不在界面出现**（社区列入发展前景） |

## 四、发展前景：陌生网友社区（本期不做，被问到再讲）

跨用户互看、点赞、评论、举报**已经实现过一轮，本期主动收敛掉**，原因：

1. 比赛阶段演示"项目和我的能力"就够，社区不是加分项而是风险项；
2. 社区必须配套**账号体系 + 内容审核 + 举报处置**三项，缺一项就会被问倒；
3. 结论：列入发展前景（文档 §8.3），被评委问到再答"这是验证产品价值之后的第二曲线"。

### 未来要做社区，还差最后一块拼图：账号

现在"这是谁的卡"是靠**浏览器的本地标识**（localStorage 里一个随机 id）判断的，所以：

- 换浏览器、清缓存、换电脑 → 那张卡就不再"是你的"，你就撤不下来了
- 别人也可以随便填昵称，无法追责

**要做成真正的陌生网友社区，下一步需要轻量账号**（三选一）：

1. 邮箱/手机号 + 验证码（最通用）
2. 第三方登录（微信 / GitHub OAuth，最快但要申请）
3. 只做"昵称 + 密码"的极简账号（黑客松够用，10 分钟能加）

> 建议顺序：**先上路线 A 让朋友试玩 → 收集反馈 → 再加极简账号 → 再上路线 B 正式部署。**

## 五、上线前自查（打勾用）

- [ ] 服务器能通过公网 IP 访问到页面
- [ ] 展示墙默认是空的（没有别人的私密数据被带上去）
- [ ] 换一个手机/浏览器访问，能互相看到并点赞、评论
- [ ] 用别人的身份撤下我的卡片 → 被拒绝
- [ ] 3 个不同设备举报同一张卡 → 自动消失
- [ ] 连续快速发 10 条评论 → 被限流
- [ ] 知道数据库文件在哪、怎么备份、怎么清空
