# 复盘通 ReviewPal · 项目文档

> OPC 黑客松参赛作品 · 版本 **V2.1**（2026-10-17）
> 一句话：把「每日进步五问」变成打卡卡片的工具 —— 填五问 → 自动判定**推进度** → 生成可导出 PNG 的复盘卡 → 沉淀成打卡墙（热力图 + 连续天数）。
>
> **项目方向（报备口径）**：解决「**长期目标立好了，日常却被琐事占满，说不清今天有没有推进目标**」的问题 —— 每天 2 分钟答「每日进步五问」，系统判出 5 档**推进度**（含 0-100 分与判定依据），生成可导出 PNG 的复盘卡，沉淀成打卡墙与月热力图。
> **主产品**：**Android App**（本地优先 / 离线可用 / API Key 入 Android Keystore / 含每日提醒）；**次产品**：**电脑网页版**（零依赖 Node，双击 `start.bat` 即开）。

---

## 1. 项目介绍

### 1.1 要解决的问题
很多人每天都在"立目标"，却说不清**今天做的这件事，到底有没有帮到目标**。常见打卡工具只记录"打卡了 / 没打卡"，最多加一句心情——它们回答不了三个关键问题：

- 我今天**原本计划**做什么？
- 我**实际**做了什么？
- 这两者之间，**差距出在哪**？

### 1.2 我们的做法
复盘通把「每日进步五问」变成一次 2 分钟的睡前复盘，并把它折算成一个可比较的指标——**推进度**，再渲染成一张可带走、可沉淀的复盘卡。

- **目标用户**：有目标（备考、保研、写作、健身、做产品…）但容易"计划与执行脱节"的个人。
- **产品定位**：**目标复盘打卡工具**。**不做任何心理 / 情绪功能**（唯一例外：复盘卡末尾一句可更换的鸡汤，内置 100 句可随机 / 手动挑选）。

### 1.3 与"记流水账"的区别
| | 普通打卡 / 日记 | 复盘通 |
|---|---|---|
| 记录对象 | 做了什么 | **计划 vs 实际 vs 目标** 三方对照 |
| 可比较性 | 无 | **推进度 5 档 + 0-100 分 + 判定依据** |
| 反馈闭环 | 无 | AI 结论**逐条可改**，改动进 `edit_history` 反哺下一轮 |
| 沉淀 | 时间线 | **复盘卡（可导出）+ 月热力图 + 连续天数** |

## 2. 核心功能

1. **每日五问（一步一问）**：长期目标、短期目标、今天原本的计划、今天实际做了什么（含自评"是否有助于目标"）、保持 / 优化、明天的任务。一屏一题，可上一问 / 下一问，支持"保存草稿"与"重置"。
2. **推进度判定**：**用户自评优先、关键词兜底** → 5 档（超额达成 / 按计划达成 / 部分完成 / 偏离目标 / 未推进）+ 0-100 分 + 判定依据；整页配色随档位变化。
3. **人在回路（Human-in-the-loop）**：AI 整理的结论逐条摊开、**每一格都能直接改**，改动写入 `edit_history`（人机协同证据）；生成完成后界面自动跳到该区块。
4. **每日复盘卡**：五问排版 + 推进度（圆环 + 分数）+ 今日一句，**一键导出 PNG 并保存到手机相册**；保存后自动进入打卡墙。
5. **坚持可视化**：月热力图（跟随主题色）+ 连续天数（中断不清零、只降级）。
6. **打卡墙**：全部记录，按推进度筛选 + 搜索 + 回看 + 删除（删除二次确认）。
7. **每日提醒**（移动端）：本地通知，可开关 / 可设时间（闹钟式时/分滚轮）/ 可发测试提醒。
8. **Token 用量**：设置页可看「今日 / 本月 / 累计」token 消耗（真实调用后自动累计；Mock 模式显示"无用量"）。
9. **三套主题**：暖色极简 / 赛博朋克 / 晴空蓝调（可跟随系统）。

## 3. 技术实现

### 3.1 两种形态（都真实可运行）
| | Android App（旗舰 · 本地优先） | 电脑网页版 |
|---|---|---|
| 运行方式 | 安装 APK（侧载） | 双击 `start.bat` → 浏览器打开 `http://localhost:8787` |
| 数据存放 | **手机本地 IndexedDB**（离线可用） | 本机 SQLite 单文件 `data/reviewpal.db` |
| 联网时机 | **只在调用大模型时** | 调用大模型时 |
| API Key | **Android Keystore**（加密存储） | 后端 `.env`（前端只见掩码） |
| 打包 | Capacitor 7 → `gradlew assembleDebug` | 无（源码即运行） |

### 3.2 架构
- **前端**：原生 JS、**零构建**（无框架、无打包步骤）。`web/index.html`（界面 + 主逻辑）+ `web/local.js`（本地优先存储层）+ `web/enhance.js`（移动端导航 / 提醒 / 主题 / 视觉）+ `web/icons.js`（底部图标）+ `web/rp-core.js`（护栏纯函数）。
- **本地优先（App）**：`local.js` 在原生环境里**就地接管** `/api/*` 请求，用手机本地库应答，完全不依赖电脑后端；只有"调模型"才走网络。
- **后端（网页版）**：**零依赖 Node**，只用 `node:http` / `node:sqlite` / `fetch`，**不需要 npm install**。路由 + 调模型 + 契约校验 + SQLite 读写。
- **护栏纯函数**：`web/rp-core.js` 提供 `inferProgress`（推进度推断）与 `validate`（数据契约校验）——**前后端共用同一份判定逻辑**，避免"两边漂移"；配 **15 条核心用例**（`node tests/rp-core.test.js` → 15 passed）。
- **数据契约**：`docs/review-record.schema.json`（统一数据契约 v3），两阶段校验（AI 输出 / 入库）。
- **模型**：**双轨** —— 真实模型（DeepSeek / 智谱 GLM / Kimi / OpenAI / 自定义接口）+ **Mock 兜底**（断网 / 无 Key 也能完整演示动线）。
- **密钥安全**：前端**从不持有明文 Key**；网页版 Key 只写后端 `.env`，App 内 Key 只进 Android Keystore（`@aparajita/capacitor-secure-storage`）。

### 3.3 Android
- **Capacitor 7**，`appId=com.reviewpal.app`，`appName=复盘通`。
- 4 个原生插件：`@aparajita/capacitor-secure-storage`（Keystore）、`@capacitor/app`（返回键接管）、`@capacitor/local-notifications`（每日提醒）、**自研 `SaveImage`**（把复盘卡 PNG 写入系统相册，Android MediaStore）。
- Manifest 含通知 / 精确闹钟 / 开机自启等权限；提醒通道独立创建，可测试。

### 3.4 目录结构
```
reviewpal/
├─ README.md / 如何运行.md / worklog.md
├─ start.bat / start.sh / package.json / .env.example
├─ web/        前端（index.html + rp-core.js + local.js + icons.js + enhance.js）
├─ server/     零依赖 Node 后端（index / classify / schema / db + prompts/）
├─ tests/      核心用例（rp-core.test.js · 15 条）
├─ mobile/     Capacitor 7 工程（capacitor.config.json + www/ + android/）
├─ docs/       项目文档 / 契约 / 部署指南 / test-data/
└─ dist/       可安装的 APK
```

## 4. 安装与运行
- **手机（推荐）**：安装 `dist/ReviewPal-debug.apk`（安卓侧载）。
- **电脑**：装 Node（建议 v24，最低 v22.5）→ 双击 `start.bat` → 浏览器打开 `http://localhost:8787`。
- **自己打包 App**：改完 `web/*` → 拷进 `mobile/www` → `npx cap sync android`（**必须**，否则包内是旧前端）→ `gradlew assembleDebug`。

> 详细步骤与常见问题见 **`如何运行.md`**。

## 5. 测试数据与验证
- **测试数据**：`docs/test-data/demo-records.json` —— **10 条脱敏合成记录**，覆盖全部 5 档推进度、日期铺开便于看热力图；每条记录的 `progress` 由 `rp-core.js` 的 `inferProgress` 生成并通过 `validate` 校验（**数据与护栏逻辑严格一致**）。
- **核心用例**：`node tests/rp-core.test.js` → **15 passed / 0 failed**。
- **静态检查**：全部 JS `node --check` 通过。
- **打包验证**：`gradlew assembleDebug` **BUILD SUCCESSFUL**，且 APK 内 `assets/public` 与 `web/` 源码**逐字节一致**。
- **接口验证**：网页版 `GET /` → 200；`GET /api/usage` → 200。

## 6. 前景与路线图（未来规划 · 尚未实现）

> 以下为**规划**，当前版本**均未实现**，请勿当作已有功能。

- **近期 · 可分享**：复盘卡导出 PNG（已实现）→ 追加"一键生成分享图 / 分享文案"，零服务器即可传播。
- **中期 · 社区**：多人打卡墙 —— 公开墙、点赞、评论、按推进度围观。**前提**：需要服务端与用户标识，**与当前"本地优先 / 离线可用"的定位冲突**，需专门设计（数据归属、隐私开关、举报机制）。
- **长期**：目标树（长期目标 → 周计划 → 日任务）、周 / 月复盘、多端同步（端到端加密）。
